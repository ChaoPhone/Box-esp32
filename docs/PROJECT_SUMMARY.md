# B-Box 实体交互游戏控制器

> 一个 IMU 姿态驱动的实体推箱子游戏控制器。
> 你不需要手柄，不需要屏幕——拿起这个盒子，推、翻、倾斜，角色就动。

---

## 1. 项目概述

B-Box 是一个基于 **ESP32-S3 + MPU6050 IMU** 的实体交互控制器。玩家通过物理动作（推动、倾斜、翻转）来控制 Unity 推箱子游戏（A-Box）中的角色，并获得电机震动的即时物理反馈。

### 1.1 一句话

**把物理世界的手势，变成了游戏里的操作。**

### 1.2 系统架构

```
┌─────────────────────┐         ESP-NOW          ┌──────────────────────┐
│  A 板 箱子端        │ ◄──────────────────────► │  B 板 桥接端          │
│  MPU6050 IMU        │    EVT/HEARTBEAT/IMUQ →   │  USB CDC → PC/Unity  │
│  手势识别 + 电机     │    ← ACK/HAPTIC/STATE     │  协议过滤转发         │
└─────────────────────┘                           └──────────┬───────────┘
                                                             │ USB CDC
                                                    ┌────────┴───────────┐
                                                    │  PC / Unity A-Box   │
                                                    │  推箱子游戏          │
                                                    └──────────────────────┘
```

- **A 板（箱子端）**：ESP32-S3 + MPU6050，负责原始传感器采样、Mahony 互补滤波姿态解算、手势识别、电机反馈
- **B 板（桥接端）**：ESP32-S3，负责 ESP-NOW 无线接收、协议行过滤、USB 串口透传到 PC
- **A-Box（Unity）**：推箱子游戏逻辑 + Web 前端调试面板，接收标准文本协议控制角色

## 2. 核心技术亮点

### 2.1 姿态不敏感的推动检测

传统方案直接比较传感器轴加速度，盒子放置姿态变化后方向就乱了。

我们的做法：**Mahony 互补滤波 → 四元数倾斜补偿 → 去 yaw → 机体航向系判向**。无论盒子平放、侧放还是斜放，前永远是盒体箭头方向，不受 yaw 漂移和放置姿态影响。

```
传感器加速度 → quatRotateWorld（转到世界帧）
            → deYawHorizontal（去掉yaw，锚定机体轴）
            → 高通滤波去DC → 过阈值峰值捕获 → 向量最大分量判向
```

- 峰值捕获窗：120ms 内追踪最强样本，一次推动 = 恰好一条 EVT
- 回摆抑制：推完回位不误触发
- 再武装迟滞：信号须回落安静才能再次触发

### 2.2 分层手势交互系统

不同角度区间触发不同语义，避免手势冲突：

| 角度范围 | 持续时间 | 触发 | 语义 |
|---|---|---|---|
| < 45° | — | — | 正常游戏区域 |
| 45°–90° | 3s | MARBLE_ENTER/EXIT | 进入/退出弹珠模式 |
| 90°→110°→回落 | < 0.5s | UNDO | 快速翻转撤销 |
| > 110° | 2s | RESET | 长时间翻面重置 |

所有手势检测通过四元数提取 pitch/roll 的最大绝对值来判断，与固件 pushDetect 共享同一套姿态数据源。

### 2.3 持续状态替代离散事件

倾斜不再以离散 EVT 事件上报（"触发一次"→"等待回正"→"再触发"），改为 **TILTS 持续状态消息**，与 IMUQ 四元数同频 20Hz 上报。宿主侧实时获取 pitch/roll 角度，用于弹珠模式的物理模拟。

### 2.4 非阻塞实时电机反馈

所有手势触发均有震动确认（LEDC PWM 驱动，255 最大力度），采用非阻塞计时器，不影响 200Hz IMU 采样循环。

### 2.5 双板无线 MAC 对传

A/B 板通过 ESP-NOW 点对点单播通信，MAC 地址固定编译期绑定，接收端做源 MAC 过滤 + 协议行合法性校验，丢弃噪声帧。B 板每 5 秒输出链路统计（帧数/丢帧/外来干扰）。

## 3. 调试与工程实践亮点

### 3.1 Web 前端实时调试面板

在没有 Unity 的情况下也能独立验证硬件：Web Serial API 直连 COM 口，解析全部上行消息并实时可视化。

- 消息流实时显示，支持按 TYPE 过滤（EVT/TILTS/IMUQ/LOG/UNKNOWN）
- 推动方向罗盘：Canvas 2D 实时绘制动态矢量、阈值圈、判定方向
- 姿态立方体：CSS 3D 实时渲染四元数姿态
- 事件统计面板：按方向分类计数
- **自动 ACK 回复**：收到 EVT 自动回 ACK,seq，停止板子重传（解决了 EVT 刷屏问题）
- UNKNOWN 过滤：默认隐藏未识别消息，可手动开启调试

### 3.2 脏帧溯源调试

B 板桥接端在 `forwardToPc` 中增加 DBG,JUNK 调试输出：遇到非协议行时，不再只做静默丢弃，而是打印 `DBG,JUNK,len=<长度>,<原始内容>`，方便溯源噪声来源。实际运行中 `dropped=0`，验证了 ESP-NOW MAC 对传过滤的有效性。

### 3.3 协议驱动开发

以 **PROTOCOL.md 为单一事实来源**，固件（C++）和 Unity（C#）和 Web（TypeScript）三方严格按照同一份协议文档实现。协议设计遵循向前兼容原则（未知 TYPE 回 NAK、多余字段忽略），方便持续迭代。

### 3.4 迭代式手势调参

手势阈值从最初的理论值，通过连接 Web 面板观察实际传感器数据分布，逐步收敛到合理区间。例如推动阈值从 0.25g 调整到 0.20g，翻面阈值从 80° 调整为 110° 以避免和弹珠区间重叠。

## 4. 混合方案探索：戒指 SDK

在 Unity A-Box 项目中预留了**智能戒指输入通道**（`UdpInput.cs` + `InputHub.cs`），通过局域网 UDP 接收戒指 SDK 的姿态和按键数据，与 B-Box 的 IMU 输入并行工作。

**探索方向**：
- 戒指做 **离散命令触发**：确认/撤销/重置（弥补翻面手势的误判风险）
- B-Box 做 **连续姿态输入**：推动移动 + 倾斜弹珠（发挥 IMU 高采样率优势）
- 两种输入源通过 `InputHub` 统一汇聚，游戏逻辑层不做区分

当前状态：UDP 通道和 `GameCommand` 映射已预留，待戒指 SDK 接入后直接打通。
