# B Box ESP32 实体交互桥接说明

## 1. 当前系统定位

本项目不再使用戒指作为交互设备。

所有主要游戏输入都来自实体箱子：

- 实体箱子内部使用 ESP32-S3 作为主控；
- MPU6050 负责测量加速度和角速度；
- 玩家移动、举起、旋转实体箱子；
- ESP32 在本地完成动作识别；
- Python 桥接程序只负责把高层动作转发给 Unity；
- Unity 根据高层动作改变虚拟箱子和游戏状态；
- Unity 可反向发送震动命令，由 ESP32 控制震动马达。

系统主链路：

```text
玩家实体动作
    ↓
MPU6050
    ↓ I²C
ESP32-S3：滤波、积分、状态机、动作判定
    ↓ USB 串口
esp32_bridge.py
    ↓ UDP 127.0.0.1:47800
Unity
```

反向触觉链路：

```text
Unity 游戏事件
    ↓ UDP 127.0.0.1:47801
esp32_bridge.py
    ↓ USB 串口
ESP32-S3
    ↓
震动马达
```

## 2. 已确定的两类实体交互

### 2.1 平移 20 cm

玩家把实体箱子向上、下、左、右中的某一方向移动约 20 cm。

当 ESP32 判断一次完整位移达到目标范围后，向 Unity 上报一次离散移动事件：

```text
MOVE_UP
MOVE_DOWN
MOVE_LEFT
MOVE_RIGHT
```

每次实体移动只对应虚拟箱子移动一格。

### 2.2 举起后旋转约 45°

玩家先举起实体箱子，再向指定方向旋转约 45°。

这类动作可以映射到：

```text
ROTATE_CW_45
ROTATE_CCW_45
```

如果实际交互是“向某个方向倾斜”而不是“绕竖直轴旋转”，则建议改为：

```text
TILT_UP_45
TILT_DOWN_45
TILT_LEFT_45
TILT_RIGHT_45
```

两者的传感器判定方式不同：

- 绕竖直轴旋转：主要依赖陀螺仪短时间积分；
- 向侧面倾斜：主要利用重力方向计算 Roll/Pitch，通常更稳定。

MPU6050 没有磁力计，因此无法长期稳定地给出绝对航向角。  
但“举起后在较短时间内旋转约 45°”可以通过陀螺仪积分完成。

## 3. 为什么不能直接对加速度裸二次积分

理论关系为：

```text
加速度积分一次得到速度
速度再积分一次得到位移
```

但 MPU6050 存在：

- 零偏；
- 噪声；
- 重力分量；
- 安装误差；
- 姿态变化；
- 温度漂移。

即使只有很小的加速度误差，二次积分后也会迅速变成明显的距离误差。

因此，不建议使用以下简单方案：

```cpp
velocity += accel * dt;
position += velocity * dt;
if (position > 0.20f) {
    trigger();
}
```

正式实现必须采用“动作分段 + 静止归零”的短时惯性估计。

推荐思路：

1. 静止时标定加速度和陀螺仪零偏；
2. 根据当前姿态估计重力方向；
3. 从测得加速度中减去重力；
4. 检测动作开始；
5. 只在一次动作窗口内积分；
6. 检测动作结束；
7. 使用 ZUPT（Zero Velocity Update，零速度更新）把速度强制归零；
8. 判断主方向和估算位移；
9. 达到阈值后只发送一次移动事件；
10. 等箱子重新稳定后才允许下一次动作。

这里的位移积分不是长期定位，而是只估计一次几百毫秒到一两秒的短动作。

## 4. 推荐的 ESP32 状态机

### 4.1 总体状态

```text
BOOT
  ↓
CALIBRATING
  ↓
STABLE
  ├── 检测到平移动作 ──> TRANSLATING
  └── 检测到举起动作 ──> LIFTED
```

平移分支：

```text
STABLE
  ↓
TRANSLATING
  ↓
MOVE_TRIGGERED
  ↓
WAIT_STABLE
  ↓
STABLE
```

旋转分支：

```text
STABLE
  ↓
LIFTED
  ↓
ROTATING
  ↓
ROTATE_TRIGGERED
  ↓
WAIT_PLACED
  ↓
STABLE
```

### 4.2 为什么需要状态机

状态机用于防止：

- 一次移动触发多次；
- 箱子放下时误判为平移；
- 震动马达造成误触发；
- 持续晃动产生连续输入；
- 举起与平移两套动作互相冲突。

## 5. 平移 20 cm 的建议判定逻辑

### 5.1 动作开始

满足以下条件之一可认为平移动作开始：

- 水平线性加速度超过阈值；
- 加速度变化率 Jerk 超过阈值；
- 连续若干采样点显示同一方向运动。

初始建议：

```text
采样频率：100 Hz
动作开始加速度阈值：0.18～0.35 g
连续确认时间：30～60 ms
```

### 5.2 重力去除

MPU6050 测到的是“线性运动加速度 + 重力”。

需要先估计姿态，再把加速度转换到世界坐标系并减去重力。

如果箱子平移时始终保持水平，可以先使用简化版本：

- 静止时记录三轴重力向量；
- 平移阶段假设姿态变化较小；
- 从实时加速度中减去静止重力向量。

如果玩家平移时会明显倾斜箱子，必须使用互补滤波或 Madgwick 等姿态估计方法。

### 5.3 短时间积分

每次动作开始时：

```text
velocity = 0
position = 0
```

在动作窗口内：

```text
velocity += linear_acceleration × dt
position += velocity × dt
```

为减小误差，可使用梯形积分，而不是最简单的欧拉积分。

### 5.4 动作结束与零速度更新

满足以下条件可认为移动结束：

- 线性加速度回到静止范围；
- 陀螺仪角速度较小；
- 状态连续稳定 100～250 ms。

动作结束后：

```text
velocity = 0
```

这一步是 ZUPT，可显著限制积分漂移。

### 5.5 方向判断

比较世界坐标系下的 X/Y 位移绝对值：

```text
abs(dx) > abs(dy) -> 左或右
abs(dy) > abs(dx) -> 上或下
```

建议增加方向优势比：

```text
主轴位移 > 次轴位移 × 1.5
```

否则将该动作判为不确定，不向 Unity发送。

### 5.6 20 cm 判定范围

不要要求积分结果必须精确等于 200 mm。

初始建议：

```text
有效目标范围：140～300 mm
明显不足：小于 100～120 mm
明显异常：大于 400～500 mm
```

最终阈值必须通过实测标定。

更稳妥的触发条件是同时满足：

```text
主方向明确
+
短时位移估计达到阈值
+
动作已经停止
+
箱子未处于举起状态
```

## 6. 举起并旋转 45° 的建议判定逻辑

### 6.1 举起检测

可组合以下信号：

- 一次明显的竖直加速度；
- 箱子离开桌面后振动特征改变；
- 姿态发生变化；
- 按项目结构增加底部接触开关。

只依赖 MPU 时，建议用状态组合而不是单一阈值。

初始建议：

```text
举起触发加速度变化：0.20～0.50 g
举起确认时间：80～200 ms
```

### 6.2 旋转检测

如果是绕竖直轴旋转：

```text
angle_z += gyro_z × dt
```

在短时窗口内累计：

```text
angle_z >= +45° -> ROTATE_CW_45
angle_z <= -45° -> ROTATE_CCW_45
```

建议使用带滞回的范围：

```text
触发阈值：38～45°
确认阈值：45～55°
```

达到阈值后只触发一次，必须放回或回到稳定状态后才能再次触发。

### 6.3 倾斜交互

如果是向某方向倾斜，建议直接根据重力向量计算 Roll/Pitch。

初始建议：

```text
触发角度：35～45°
确认角度：45～55°
回零角度：小于 15～20°
```

这种方式通常比绕竖直轴旋转更容易稳定实现。

## 7. ESP32 与 Python 的串口协议

### 7.1 ESP32 上报动作

格式：

```text
EVT,<sequence>,<action>,<value>,<timestamp_ms>
```

示例：

```text
EVT,12,MOVE_RIGHT,203.5,153210
EVT,13,ROTATE_CW_45,47.2,154008
```

字段含义：

| 字段 | 含义 |
|---|---|
| `EVT` | 动作事件 |
| `sequence` | 递增序号 |
| `action` | 高层动作名称 |
| `value` | 位移 mm 或角度 degree |
| `timestamp_ms` | ESP32 启动后的毫秒时间 |

Python 在成功转发给 Unity 后回复：

```text
ACK,12
```

ESP32 若在规定时间内没有收到 ACK，可重发相同 sequence。

Python 会对 sequence 去重，因此重发不会导致 Unity 重复移动。

### 7.2 心跳

ESP32 建议每 500～1000 ms 发送：

```text
HEARTBEAT,153500,STABLE
```

可用状态：

```text
CALIBRATING
STABLE
TRANSLATING
LIFTED
ROTATING
WAIT_STABLE
ERROR
```

### 7.3 调试 IMU 数据

调试模式下可输出：

```text
IMU,ax,ay,az,gx,gy,gz
```

正式运行时应关闭高频 IMU 日志。

## 8. Python 到 Unity 的 UDP 协议

默认地址：

```text
127.0.0.1:47800
```

Python 默认只发送动作名：

```text
MOVE_RIGHT
ROTATE_CW_45
LIFT
PLACE
```

Unity 应将键盘输入与实体输入汇聚到同一套游戏函数。

例如：

```text
键盘右方向键
          ┐
          ├──> RequestMove(Right)
MOVE_RIGHT
          ┘
```

不要为实体箱子复制另一套移动规则。

## 9. Unity 到 ESP32 的震动反馈

Unity 向：

```text
127.0.0.1:47801
```

发送：

```text
HAPTIC,<pattern>,<strength>,<duration_ms>
```

示例：

```text
HAPTIC,PUSH,100,60
HAPTIC,WALL,180,120
HAPTIC,SUCCESS,255,600
HAPTIC,FAIL,220,300
```

桥接程序会原样转发给 ESP32。

建议震动映射：

| 游戏事件 | 震动模式 |
|---|---|
| 移动成功 | 短而轻 |
| 撞墙 | 短而强 |
| 箱子到达目标点 | 双脉冲 |
| 撤销 | 单次中等 |
| 通关 | 长或节奏震动 |
| 操作无效 | 两次短震 |

震动期间以及结束后 50～150 ms 内，ESP32 应暂停产生新的 IMU 动作事件，避免马达振动误触发。

## 10. 需要重点调节的参数

建议所有参数集中放在 ESP32 的一个配置文件中。

```cpp
struct MotionConfig {
    float sample_rate_hz;

    float move_start_accel_g;
    float move_stop_accel_g;
    float stationary_gyro_dps;

    float min_move_distance_mm;
    float target_move_distance_mm;
    float max_move_distance_mm;

    float direction_dominance_ratio;
    uint32_t stable_confirm_ms;
    uint32_t max_motion_window_ms;

    float lift_accel_threshold_g;
    uint32_t lift_confirm_ms;

    float rotate_trigger_deg;
    float rotate_release_deg;

    uint32_t haptic_guard_ms;
};
```

推荐初始值：

| 参数 | 初始值 |
|---|---:|
| 采样频率 | 100 Hz |
| 平移动作开始加速度 | 0.25 g |
| 平移动作停止加速度 | 0.08 g |
| 静止角速度 | 8 °/s |
| 最小有效位移 | 140 mm |
| 目标位移 | 200 mm |
| 最大合理位移 | 320 mm |
| 主方向优势比 | 1.5 |
| 稳定确认时间 | 180 ms |
| 最大动作窗口 | 1500 ms |
| 举起加速度阈值 | 0.30 g |
| 举起确认时间 | 120 ms |
| 旋转触发角度 | 42° |
| 旋转释放角度 | 15° |
| 震动后屏蔽时间 | 100 ms |

以上只是首轮标定起点，不是最终值。

## 11. 标定流程

### 11.1 传感器静态标定

箱子放平并保持不动 3～5 秒：

1. 采集加速度平均值；
2. 采集陀螺仪平均值；
3. 保存零偏；
4. 检查静止噪声。

每次上电可自动执行一次。

### 11.2 轴向确认

分别向四个方向移动箱子，记录：

- 哪一轴变化最大；
- 正负方向是否与 Unity 一致；
- MPU 安装方向是否需要映射。

建立明确映射：

```text
传感器 +X -> 游戏右
传感器 -X -> 游戏左
传感器 +Y -> 游戏上
传感器 -Y -> 游戏下
```

### 11.3 平移样本采集

每个方向至少记录：

- 正常移动 20 次；
- 偏短移动 10 次；
- 偏长移动 10 次；
- 轻微晃动 10 次；
- 移动后快速放下 10 次。

记录：

```text
峰值加速度
积分位移
动作时长
最终方向
是否误判
```

### 11.4 旋转样本采集

分别记录顺时针和逆时针：

- 约 30°；
- 约 45°；
- 约 60°；
- 举起但不旋转；
- 平移但不举起。

目标是确保：

- 30° 不触发或很少触发；
- 45° 稳定触发；
- 举起和放下不会触发旋转；
- 平移动作不会进入旋转状态。

## 12. Python 桥接程序使用方法

安装依赖：

```bash
pip install -r requirements.txt
```

指定串口运行：

```bash
python esp32_bridge.py --port COM5
```

自动寻找串口：

```bash
python esp32_bridge.py
```

指定 Unity 端口：

```bash
python esp32_bridge.py --port COM5 --unity-port 47800
```

程序具备：

- ESP32 串口自动重连；
- Unity UDP 转发；
- 事件 sequence 去重；
- ACK 回复；
- ESP32 心跳提示；
- Unity 震动命令反向转发；
- 调试日志输出。

## 14. 验收标准

### 平移交互

- 每个方向连续测试 50 次；
- 正确识别率达到可演示要求；
- 一次移动只触发一次；
- 轻微晃动不触发；
- 放下箱子不误触发；
- 四方向映射正确；
- 操作延迟没有明显违和感。

### 旋转交互

- 举起但不旋转时不触发；
- 旋转 45° 能稳定触发；
- 同一动作只触发一次；
- 放回箱子后能够重新进入待机状态；
- 平移动作不会误判为旋转。

### 通信

- ESP32 断开后能够自动重连；
- 重传不会造成 Unity 重复执行；
- Unity 保留键盘调试能力；
- 震动马达工作时不会造成误触发或 ESP32 复位。

## 15. 当前最重要的工程原则

1. ESP32 输出高层动作，不把原始 IMU 判断交给 Unity。
2. 平移识别使用短时分段积分，不做长期惯性定位。
3. 每次动作必须经历开始、触发、稳定恢复。
4. 平移和举起旋转必须是互斥状态。
5. 先完成 USB 有线闭环，再考虑 ESP-NOW 无线化。
6. 先实现四方向平移，再实现举起旋转。
7. 所有阈值必须从真实样本日志中得到，不靠主观猜测。
