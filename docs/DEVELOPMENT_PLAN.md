# B Box ESP32 实体交互实施计划

## 1. 最终目标

完成以下可靠闭环：

```text
实体箱子移动约 20 cm
或
实体箱子举起并旋转约 45°
        ↓
ESP32-S3 + MPU6050 识别动作
        ↓
Python Bridge 转发 UDP
        ↓
Unity 改变虚拟箱子或游戏状态
        ↓
Unity 返回游戏反馈
        ↓
ESP32 驱动震动马达
```

实施顺序必须从最短闭环开始，不能同时铺开全部功能。

---

## 2. 阶段 0：冻结交互定义

### 目标

在写动作算法前，把每种实体动作与游戏语义固定下来。

### 必须形成的表格

| 实体动作 | 游戏动作 | 是否必须完成 |
|---|---|---|
| 向右平移约 20 cm | 虚拟箱子右移一格 | 必须 |
| 向左平移约 20 cm | 虚拟箱子左移一格 | 必须 |
| 向前平移约 20 cm | 虚拟箱子上移一格 | 必须 |
| 向后平移约 20 cm | 虚拟箱子下移一格 | 必须 |
| 举起并顺时针约 45° | 待团队定义 | 第二阶段 |
| 举起并逆时针约 45° | 待团队定义 | 第二阶段 |
| 其他实体动作 | 待团队定义 | 可选 |

### 需要明确

1. 实体箱子在桌面滑动，还是被拿起后移动？
2. 20 cm 是否存在物理标记、格子或边界？
3. 旋转是绕竖直轴转动，还是向某方向倾斜？
4. 每次操作结束后，实体箱子是否回到中心位置？
5. 游戏中哪些事件需要震动反馈？

### 完成标准

团队成员对同一个动作的理解一致，并能由一个人现场重复演示。

---

## 3. 阶段 1：打通 Unity UDP 输入

### 目标

先证明 Unity 能接收实体动作协议，不接 ESP32，不接 MPU。

### 工作

1. 扩展 Unity `UdpInput`；
2. 支持：
   - `MOVE_UP`
   - `MOVE_DOWN`
   - `MOVE_LEFT`
   - `MOVE_RIGHT`
   - `ROTATE_CW_45`
   - `ROTATE_CCW_45`
3. 保留键盘输入；
4. 键盘和 UDP 调用同一个游戏控制函数；
5. 编写一个临时 UDP 测试脚本，手动发送动作。

### 验收

- 每条 UDP 消息只触发一次；
- 连续发送四方向动作正确；
- 键盘仍可正常控制；
- Unity 不因为未知消息报错或卡死。

### 禁止事项

本阶段不要开始调 IMU。

---

## 4. 阶段 2：打通 ESP32 串口通信

### 目标

ESP32 暂时不读取 MPU，只通过固定或按键触发事件。

### 工作

ESP32 定时或按按钮发送：

```text
EVT,1,MOVE_RIGHT,200,1000
```

Python：

1. 连接 COM 口；
2. 解析事件；
3. 通过 UDP 转发；
4. 回复：
   ```text
   ACK,1
   ```
5. 对相同 sequence 去重；
6. 测试断线重连。

### 验收

```text
ESP32 测试动作
→ Python 收到
→ Unity 移动一次
→ ESP32 收到 ACK
```

连续测试至少 100 次，不允许重复移动。

---

## 5. 阶段 3：跑通 MPU6050 原始数据

### 目标

只读取和记录数据，不做动作判定。

### 工作

1. 确认 I²C 地址；
2. 确认安装方向；
3. 设置采样频率 100 Hz；
4. 上电静止标定；
5. 输出：
   ```text
   IMU,ax,ay,az,gx,gy,gz
   ```
6. 保存测试日志。

### 采集动作

- 静止 10 秒；
- 四方向各平移 20 次；
- 轻微晃动；
- 举起；
- 放下；
- 顺时针旋转；
- 逆时针旋转；
- 开启震动马达。

### 验收

能够清楚看到：

- 平移时主要加速度轴；
- 旋转时主要角速度轴；
- 静止噪声范围；
- 震动马达造成的干扰。

---

## 6. 阶段 4：实现平移动作开始与结束检测

### 目标

暂时不估计 20 cm，只识别“一次平移动作”。

### 状态机

```text
STABLE
→ TRANSLATING
→ WAIT_STABLE
→ STABLE
```

### 工作

1. 标定静止阈值；
2. 用线性加速度或 Jerk 检测动作开始；
3. 用加速度和角速度共同判断停止；
4. 加入稳定确认时间；
5. 一次动作只输出一条调试日志。

### 验收

- 一次平移只检测一次；
- 轻微晃动不算完整动作；
- 箱子放下不会立即重复触发；
- 四方向动作窗口能被稳定切分。

---

## 7. 阶段 5：实现短时积分与 20 cm 判定

### 目标

在每次已切分的动作窗口内估计位移。

### 工作

1. 重力去除；
2. 坐标系转换；
3. 梯形积分得到速度；
4. 再积分得到位移；
5. 动作开始时清零；
6. 动作停止时执行 ZUPT；
7. 判断主方向；
8. 加入最小、目标、最大位移范围；
9. 触发 `MOVE_*`。

### 首轮建议阈值

```text
最小有效位移：140 mm
目标位移：200 mm
最大合理位移：320 mm
主方向优势比：1.5
```

### 验收方法

每个方向测试 30～50 次，记录：

- 正确；
- 漏触发；
- 重复触发；
- 方向错误；
- 距离误判。

### 决策点

如果仅靠 MPU 二次积分无法达到演示稳定性，不要继续无限调参。

按以下顺序增加约束：

1. 更严格的动作开始/结束分段；
2. 加入桌面格子或机械限位；
3. 增加底部光流、霍尔、距离或接触传感器；
4. 把“精确 20 cm”改为“完成一次明确推移动作”。

---

## 8. 阶段 6：接入 Unity 四方向移动

### 目标

让真实实体移动稳定控制游戏。

### 工作

1. ESP32 只上报高层事件；
2. Python 去重并 ACK；
3. Unity 每个事件移动一格；
4. 保留键盘兜底；
5. 测试操作节奏和冷却时间。

### 验收

- 玩家不需要看调试终端；
- 连续操作不明显迟钝；
- 一次实体移动只对应一格；
- 误操作率可以接受；
- 断线不会导致 Unity 持续移动。

这一阶段完成后，即形成最小可演示版本。

---

## 9. 阶段 7：实现举起检测

### 目标

把平移状态和旋转状态分开。

### 工作

1. 建立 `LIFTED` 状态；
2. 检测举起；
3. 举起后禁止平移动作触发；
4. 放回后重新进入 `STABLE`；
5. 测试举起、放下和晃动的区别。

### 验收

- 举起不触发平移；
- 平移不进入举起状态；
- 放下不随机触发游戏动作。

---

## 10. 阶段 8：实现 45° 旋转交互

### 目标

举起后识别一次明确旋转。

### 工作

如果绕竖直轴：

1. 进入 `LIFTED` 后清零角度；
2. 对主要陀螺仪轴积分；
3. 达到 42～50° 触发；
4. 触发后锁定；
5. 放回或回正后解锁。

如果是侧向倾斜：

1. 计算 Roll/Pitch；
2. 设置 45° 触发阈值；
3. 设置小于 15～20° 的释放阈值；
4. 加入方向映射。

### 验收

- 30° 不轻易触发；
- 45° 稳定触发；
- 60° 仍只触发一次；
- 举起不旋转不触发；
- 平移不误触发旋转。

---

## 11. 阶段 9：接入震动反馈

### 目标

建立 Unity 到实体箱子的反馈链路。

### 工作

Unity 发送：

```text
HAPTIC,PUSH,100,60
HAPTIC,WALL,180,120
HAPTIC,SUCCESS,255,600
```

Python 原样转发给 ESP32。

ESP32：

1. 驱动震动马达；
2. 回复 ACK；
3. 震动期间屏蔽动作事件；
4. 检查供电是否造成复位；
5. 根据游戏体验调整震动模式。

### 验收

- 撞墙、移动成功和通关触感可区分；
- 震动不会导致误触发；
- 震动不会导致 ESP32 重启；
- 长时间运行无明显温升或电源异常。

---

## 12. 阶段 10：无线化

### 前提

只有 USB 有线版本完全稳定后，才开始无线化。

### 推荐

```text
箱子 ESP32-S3
    ↓ ESP-NOW
接收器 ESP32-S3
    ↓ USB 串口
Python Bridge
```

上层串口协议保持不变。

### 验收

- 无线丢包时不会重复动作；
- 断线后能够恢复；
- 接收器重启后自动连接；
- 实际场地距离和干扰环境通过测试。

---

## 13. 参数调节顺序

不要同时调整全部参数。

推荐顺序：

1. 轴向映射；
2. 静止零偏；
3. 动作开始阈值；
4. 动作结束阈值；
5. 稳定确认时间；
6. 重力去除；
7. 主方向优势比；
8. 位移阈值；
9. 旋转角度阈值；
10. 震动屏蔽时间。

每次只改一类参数，并记录修改前后的测试结果。

## 17. 失败预案

### 位移积分不稳定

优先保住“动作方向识别”，不要把全部时间消耗在精确距离上。

可退化为：

```text
检测到一次明确的方向平移动作
+
动作持续时间和冲击强度达到范围
→ 移动一格
```

### Unity 修改来不及

Python 可临时模拟键盘，但正式结构仍建议 Unity 接收 UDP 高层事件。

### 无线来不及

直接使用 USB 有线演示。

### 旋转识别来不及

先保留四方向平移，把旋转作为后续加分功能。

### 震动干扰 IMU

震动期间锁定动作状态，并在震动结束后增加保护时间。
